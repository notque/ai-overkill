# Game-design skill evaluation

Run these cases when changing the skill. Judge outputs against repository evidence, capability coverage, player consequence, concrete fixes, and validation—not prose volume.

| Case | Prompt shape | Required behavior | Failure |
|---|---|---|---|
| Core loop | “Why does our combat feel repetitive?” | Inspect actual state, choices, feedback, costs, and progression; load core-loop, craft, fairness, and pacing cards as warranted. | Calls it boring without a trace or test. |
| FTUE | “Audit onboarding in this repository.” | Build a first-session path, distinguish missing evidence, cover goals, friction, learning, flow, failure, and return. | Recommends more tutorial text without comprehension evidence. |
| Economy | “Review this battle pass.” | Inspect free/paid paths, time demand, catch-up, disclosure, progression, KPI guards, and player trust. | Optimizes conversion alone. |
| Multiplayer | “Design a ranked co-op feature.” | Cover relationship intent, coordination, newcomer route, abuse, cohort, anti-cheat, alternatives, and validation. | Defaults to a global leaderboard. |
| Full diagnostic | “Run a complete game design report on this repo.” | Load all modules, produce evidence and coverage ledgers, dispose every matrix row, and sequence detailed fixes. | Samples only named systems or leaves capability rows implicit. |
| Autonomous retention improvement | “Retention is falling. Improve this game.” | Read governing local skills, inspect the full player path and evidence, run all affected packets (all 61 for systemic retention), implement reversible evidence-supported improvements, and record measurement plus welfare guards. | Proposes a generic reward, notification, or streak mechanic without diagnosing autonomy, competence, relatedness, friction, fairness, and the actual repository behavior. |
| Ambiguous idea | “We need a better hook.” | Ask for player moment if absent, generate distinct options, state risks and a cheap test. | Treats a behavioral framework as a mandate to increase compulsion. |
| Production scope | “Can our team ship this in six months?” | Use range estimates, assumptions, dependencies, content throughput, QA, team gaps, and cuts. | Gives a single date without assumptions. |

## Pass checks

1. The selected references match the issue; complete diagnostics load all modules.
2. Every material claim cites a path, observed behavior, measured signal, or inference label.
3. Each recommendation names a player-facing change, implementation scope, risk, owner, and success/quality measures.
4. The output preserves voluntary participation, accessibility, fairness, and informed paid choices.
5. The answer states missing evidence and what would change its recommendation.

## Regression probes

- Remove telemetry from a fixture: the output must report the gap, not invent metrics.
- Supply a highly engaged but negative-sentiment cohort: the output must retain the welfare guard.
- Supply a feature with no pillar fit: the output must consider a cut.
- Supply an inferred player segment: the output must label it as a hypothesis.
- Supply a retention-only prompt: the output must first inspect the game and its local implementation skills, then produce or make bounded improvements rather than waiting for a feature request.
