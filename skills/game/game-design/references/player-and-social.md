# Player contexts, needs, and motivation

Use this module to develop evidence-led hypotheses about who a feature fits and how it excludes.

## Greedy loading rule

For a focused request, load every packet in this module unless its player moment is demonstrably outside the request. For a complete repository diagnostic, load every listed packet. The packets contain the operational procedure, evidence standard, repair patterns, deliverable rubric, and failure checks.

## Packets

- [game-design-bartle-archetype-audit](./capabilities/04-game-design-bartle-archetype-audit.md): use play-style motives as feature hypotheses.
- [game-design-big-five-personality-audit](./capabilities/05-game-design-big-five-personality-audit.md): test whether a design tolerates varied comfort and novelty needs.
- [game-design-granular-player-motivation-audit](./capabilities/23-game-design-granular-player-motivation-audit.md): separate the distinct experiences a feature may satisfy.
- [game-design-player-motivation-audit](./capabilities/38-game-design-player-motivation-audit.md): audit why a player begins, continues, chooses, and returns.
- [game-design-player-need-satisfaction-audit](./capabilities/39-game-design-player-need-satisfaction-audit.md): test autonomy, competence, and relatedness in concrete moments.
- [game-design-player-persona-extractor](./capabilities/40-game-design-player-persona-extractor.md): turn evidence into falsifiable play-context personas.
- [game-design-player-perspective-reframe](./capabilities/41-game-design-player-perspective-reframe.md): restate a design issue from the player’s moment and knowledge.
- [game-design-player-segment-perception-audit](./capabilities/42-game-design-player-segment-perception-audit.md): compare how contexts interpret the same feature.
- [game-design-player-values-mapper](./capabilities/43-game-design-player-values-mapper.md): map values a game invites players to express or reject.
- [game-design-systematizing-empathizing-audit](./capabilities/51-game-design-systematizing-empathizing-audit.md): offer both rule-oriented and relationship-oriented ways into a system.

## Cross-domain checks

When a finding changes the player path, also load the adjacent module for fairness, pacing, player context, social impact, economy, and delivery feasibility. Do not treat this index as a substitute for the packets.
