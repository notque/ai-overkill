# Concept, fantasy, and loop

State the fantasy as a player verb plus consequence: “outsmart a rival through
preparation,” not “a tactical game.” Theme and feature lists support the
fantasy; they do not replace it. Derive three to five pillars that force
tradeoffs. If a feature serves neither a pillar, fantasy, nor a hard constraint,
defer it.

```text
Trigger → player choice → immediate feedback → consequence/reward → renewed goal
```

Separate this core loop from meta progression, collection, narrative, and
monetization. For every step ask what the player knows, can influence, risks,
and learns. A loop fails when an answer is missing or every turn resolves alike.

| Symptom | Inspect | First intervention |
|---|---|---|
| Feature soup | Is the loop visible below systems? | Cut a system that changes no core choice. |
| Pasted-on theme | What the player repeatedly does | Change verbs, feedback, or stakes. |
| Cosmetic choices | Costs, information, consequences | Make options differ readably. |
| Endless debate | Missing decision rule | Write a pillar or success condition. |

Frame goals as a visible desired state, a reason it matters now, available
actions, and an intelligible obstacle. Keep the immediate goal dense enough
that a new player can form an intention without a menu tour. For craft critique,
trace what the player learns to notice, predicts, tests, and masters; add
variation only after the learned pattern earns it. A design claim needs a
player-facing example and an observable test, not an authorial preference.
