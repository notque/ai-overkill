# Multiplayer, social systems, and competition

Use this module for relationships, group play, leaderboards, and comparative status.

## Greedy loading rule

For a focused request, load every packet in this module unless its player moment is demonstrably outside the request. For a complete repository diagnostic, load every listed packet. The packets contain the operational procedure, evidence standard, repair patterns, deliverable rubric, and failure checks.

## Packets

- [game-design-leaderboard-audit](./capabilities/27-game-design-leaderboard-audit.md): audit comparison systems for fairness, belonging, and abuse.
- [game-design-leaderboard-builder](./capabilities/28-game-design-leaderboard-builder.md): specify a leaderboard from social purpose through operations.
- [game-design-multiplayer-feature-audit](./capabilities/30-game-design-multiplayer-feature-audit.md): audit a shared feature as relationships, coordination, and failure recovery.
- [game-design-prosocial-session-chapters](./capabilities/45-game-design-prosocial-session-chapters.md): structure a session around contribution, recognition, and shared resolution.
- [game-design-social-satisfaction-matrix](./capabilities/50-game-design-social-satisfaction-matrix.md): map social systems to autonomy, competence, relatedness, and status.

## Cross-domain checks

When a finding changes the player path, also load the adjacent module for fairness, pacing, player context, social impact, economy, and delivery feasibility. Do not treat this index as a substitute for the packets.
