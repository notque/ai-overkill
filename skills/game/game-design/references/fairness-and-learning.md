# Fairness, failure, and learning

Players judge fairness from what they can see, predict, influence, and recover
from. Trace one failed attempt:

```text
Expectation → information → choice → result → feedback → loss → retry path
```

| Break | Player symptom | Design response |
|---|---|---|
| Opaque cause | “That came from nowhere.” | Surface the cause when it matters. |
| Weak control | “Nothing I did mattered.” | Add counterplay or narrow variance. |
| Misleading feedback | “I thought that worked.” | Align animation, UI, sound, and rules. |
| Punishing reset | “I will not retry.” | Reduce re-entry friction or retain learning. |
| Bad ramp | Boredom, then anxiety | Add one new demand at a time. |

State what randomizes, its range, visibility, and counterplay. Hidden variance
is most risky after a committed high-stakes choice. Fast play needs clear cues;
deliberate planning needs time, information, and reversibility.

Audit flow through challenge, skill, feedback speed, interruption, and recovery.
If challenge rises, introduce one demand at a time and give a safe application
before stacking it. Diagnose failure as a loop, not a loss screen: trigger,
attempt, information, consequence, retry, learning. Preserve a useful lesson
or a fair recovery when the cost is high.
