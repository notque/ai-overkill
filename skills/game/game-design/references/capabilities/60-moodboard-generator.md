# moodboard-generator

## Purpose

Assemble a legal, purposeful reference board that translates into production choices. This packet is a repository-aware operating procedure, not a label to apply to a design.

## Evidence intake

Inspect repository evidence before requesting context: art brief, owned assets, licensed references, target platform. Then inspect these capability-specific signals: signal, contrast, composition, palette, material, motion, exclusions, asset rights. Ask only for external evidence, confidential player research, decision authority, or constraints unavailable in the repository.

Mark every claim as `observed`, `documented`, `measured`, or `inferred`. Give each inference a confidence level and a disproof route.

## Method

1. Interpret mood into adjectives, color harmony, shot types, subject list, texture/material, and typography direction before searching.
2. Gather 20–40 candidates across targeted queries, inspect visually, then curate 8–16 with a hero, size roles, palette, and alt text.
3. Treat the board as a composition with hierarchy and color balance; preserve source metadata and asset rights status.

## Diagnostic questions

- What exact player moment or delivery decision is under review?
- Which capability lens above has the strongest evidence and which is only an inference?
- Which competing explanation would produce the same visible symptom?
- What is the smallest change or test that would separate them?

## Output schema

Return all of the following, not a generic summary:

- creative brief
- query plan
- candidate ledger
- keep/reject rationale
- board schema
- HTML/PNG handoff

## Failure modes

- Do not build a photo dump or curate from captions alone.
- Do not stretch images into incompatible layout roles.
- Reference images never grant reuse rights.

## Example application

When a team needs to assemble a legal, purposeful reference board that translates into production choices, begin with the available build path and the capability matrix above. Apply the named method to the affected moment, not an abstract feature description. If direct player evidence is absent, publish an evidence gap rather than a false conclusion; label the result as inferred and use the validation below to move it toward measured evidence.

## Decision procedure

1. Use `signal` as the first discriminating lens, because it is closest to the stated capability.
2. Compare it against `asset rights` before selecting a fix; this prevents a single-dimension conclusion.
3. Convert the result into `moodboard brief and asset ledger` with an owner, a quality guard, and a stop rule.

## Validation

Review hierarchy, palette coherence, shot variety, legibility, and source traceability before handoff.

## Full-diagnostic disposition

In a complete repository diagnostic, run this packet and record `assessed`, `evidence gap`, or `not applicable` with a game-specific reason. A missing artifact is a finding; it never permits silent omission.
