# game-design-ftue-hero-journey-audit

## Purpose

Shape first-time play as a short competence-building arc. This packet is a repository-aware operating procedure, not a label to apply to a design.

## Evidence intake

Inspect repository evidence before requesting context: first session, tutorial, UI, progression grants, player sessions. Then inspect these capability-specific signals: invitation, safe action, first win, complication, mentor cue, choice, earned close. Ask only for external evidence, confidential player research, decision authority, or constraints unavailable in the repository.

Mark every claim as `observed`, `documented`, `measured`, or `inferred`. Give each inference a confidence level and a disproof route.

## Method

1. Build the first session as invitation, safe action, first competence, complication, guided choice, proof, and earned close.
2. Teach a rule only when it is immediately useful; then let the player apply it.
3. Check both mechanical comprehension and emotional ownership.

## Diagnostic questions

- What exact player moment or delivery decision is under review?
- Which capability lens above has the strongest evidence and which is only an inference?
- Which competing explanation would produce the same visible symptom?
- What is the smallest change or test that would separate them?

## Output schema

Return all of the following, not a generic summary:

- first-session beat map
- rule-teaching order
- comprehension probes
- FTUE fixes

## Failure modes

- Do not turn a narrative beat sheet into an unskippable tutorial.
- Do not count completion as learning.
- Story structure must serve learning rather than force a script.

## Example application

When a team needs to shape first-time play as a short competence-building arc, begin with the available build path and the capability matrix above. Apply the named method to the affected moment, not an abstract feature description. If direct player evidence is absent, publish an evidence gap rather than a false conclusion; label the result as inferred and use the validation below to move it toward measured evidence.

## Decision procedure

1. Use `invitation` as the first discriminating lens, because it is closest to the stated capability.
2. Compare it against `earned close` before selecting a fix; this prevents a single-dimension conclusion.
3. Convert the result into `FTUE beat map` with an owner, a quality guard, and a stop rule.

## Validation

Give a neutral task after teaching; pass only if players use the rule without a prompt.

## Full-diagnostic disposition

In a complete repository diagnostic, run this packet and record `assessed`, `evidence gap`, or `not applicable` with a game-specific reason. A missing artifact is a finding; it never permits silent omission.
