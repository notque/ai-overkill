# game-design-goal-density-and-immediacy-audit

## Purpose

Check whether players can form and renew meaningful intentions. This packet is a repository-aware operating procedure, not a label to apply to a design.

## Evidence intake

Inspect repository evidence before requesting context: HUD, quest flow, level structure, player behavior. Then inspect these capability-specific signals: visible goal, reason now, near action, obstacle, horizon, competing goals. Ask only for external evidence, confidential player research, decision authority, or constraints unavailable in the repository.

Mark every claim as `observed`, `documented`, `measured`, or `inferred`. Give each inference a confidence level and a disproof route.

## Method

1. Audit visible near, mid, and long goals; their urgency, actionability, obstacles, and competing claims.
2. Count decisions with a purpose, not icons or quest markers.
3. Ensure a player can form a next intention after any completion, failure, or interruption.

## Diagnostic questions

- What exact player moment or delivery decision is under review?
- Which capability lens above has the strongest evidence and which is only an inference?
- Which competing explanation would produce the same visible symptom?
- What is the smallest change or test that would separate them?

## Output schema

Return all of the following, not a generic summary:

- goal horizon map
- dead-zone list
- objective revisions
- HUD/copy implications

## Failure modes

- Do not cure aimlessness by adding chores.
- Do not overload players with equal-priority goals.
- More markers do not equal more meaningful goals.

## Example application

When a team needs to check whether players can form and renew meaningful intentions, begin with the available build path and the capability matrix above. Apply the named method to the affected moment, not an abstract feature description. If direct player evidence is absent, publish an evidence gap rather than a false conclusion; label the result as inferred and use the validation below to move it toward measured evidence.

## Decision procedure

1. Use `visible goal` as the first discriminating lens, because it is closest to the stated capability.
2. Compare it against `competing goals` before selecting a fix; this prevents a single-dimension conclusion.
3. Convert the result into `goal-density map` with an owner, a quality guard, and a stop rule.

## Validation

Ask players what they are trying to do now and why it matters.

## Full-diagnostic disposition

In a complete repository diagnostic, run this packet and record `assessed`, `evidence gap`, or `not applicable` with a game-specific reason. A missing artifact is a finding; it never permits silent omission.
