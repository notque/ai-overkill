# game-design-roadblock-reframing

## Purpose

Convert a blocked statement into a controllable question. This packet is a repository-aware operating procedure, not a label to apply to a design.

## Evidence intake

Inspect repository evidence before requesting context: team notes, blockers, decisions, dependencies. Then inspect these capability-specific signals: claimed obstacle, constraint type, assumption, affected player moment, smallest move. Ask only for external evidence, confidential player research, decision authority, or constraints unavailable in the repository.

Mark every claim as `observed`, `documented`, `measured`, or `inferred`. Give each inference a confidence level and a disproof route.

## Method

1. Classify the obstacle as decision, knowledge, authority, dependency, capacity, conflict, or emotional avoidance.
2. Reframe from “we cannot” to a bounded question with a controllable next move.
3. Use constraint inversion, smallest proof, and explicit owner to avoid vague optimism.

## Diagnostic questions

- What exact player moment or delivery decision is under review?
- Which capability lens above has the strongest evidence and which is only an inference?
- Which competing explanation would produce the same visible symptom?
- What is the smallest change or test that would separate them?

## Output schema

Return all of the following, not a generic summary:

- roadblock diagnosis
- reframed question
- controllable moves
- escalation need
- next owner

## Failure modes

- Do not turn an external block into an individual failure.
- Do not reframe away a necessary escalation.
- Do not reframe a real external dependency into a personal mindset issue.

## Example application

When a team needs to convert a blocked statement into a controllable question, begin with the available build path and the capability matrix above. Apply the named method to the affected moment, not an abstract feature description. If direct player evidence is absent, publish an evidence gap rather than a false conclusion; label the result as inferred and use the validation below to move it toward measured evidence.

## Decision procedure

1. Use `claimed obstacle` as the first discriminating lens, because it is closest to the stated capability.
2. Compare it against `smallest move` before selecting a fix; this prevents a single-dimension conclusion.
3. Convert the result into `reframed problem and experiment` with an owner, a quality guard, and a stop rule.

## Validation

The reframe passes when it creates a concrete action or documented unblock request.

## Full-diagnostic disposition

In a complete repository diagnostic, run this packet and record `assessed`, `evidence gap`, or `not applicable` with a game-specific reason. A missing artifact is a finding; it never permits silent omission.
