# game-design-creative-unblocker

## Purpose

Turn a stalled design decision into a bounded next experiment. This packet is a repository-aware operating procedure, not a label to apply to a design.

## Evidence intake

Inspect repository evidence before requesting context: decision log, roadmap, constraints, rejected options. Then inspect these capability-specific signals: stated blockage, hidden assumption, decision owner, reversible action, evidence gap. Ask only for external evidence, confidential player research, decision authority, or constraints unavailable in the repository.

Mark every claim as `observed`, `documented`, `measured`, or `inferred`. Give each inference a confidence level and a disproof route.

## Method

1. Name the stalled decision, decision owner, fear, hidden constraint, and evidence missing.
2. Use assumption reversal, constraint tightening, subtraction, role reversal, and a deliberately bad proposal to unlock movement.
3. End with one reversible action, not a larger idea list.

## Diagnostic questions

- What exact player moment or delivery decision is under review?
- Which capability lens above has the strongest evidence and which is only an inference?
- Which competing explanation would produce the same visible symptom?
- What is the smallest change or test that would separate them?

## Output schema

Return all of the following, not a generic summary:

- block statement
- reframed question
- three moves
- chosen experiment
- owner/date

## Failure modes

- Do not psychologize a blocked decision that is waiting on authority or dependency.
- Do not confuse novel language with progress.
- Do not replace a delivery conflict with a creativity exercise.

## Example application

When a team needs to turn a stalled design decision into a bounded next experiment, begin with the available build path and the capability matrix above. Apply the named method to the affected moment, not an abstract feature description. If direct player evidence is absent, publish an evidence gap rather than a false conclusion; label the result as inferred and use the validation below to move it toward measured evidence.

## Decision procedure

1. Use `stated blockage` as the first discriminating lens, because it is closest to the stated capability.
2. Compare it against `evidence gap` before selecting a fix; this prevents a single-dimension conclusion.
3. Convert the result into `reframed question and next action` with an owner, a quality guard, and a stop rule.

## Validation

The unblock succeeds only when a named decision changes or evidence is collected.

## Full-diagnostic disposition

In a complete repository diagnostic, run this packet and record `assessed`, `evidence gap`, or `not applicable` with a game-specific reason. A missing artifact is a finding; it never permits silent omission.
