# Fairness, failure, randomness, and learning

Use this module when a challenge, loss, reset, or random outcome drives player sentiment.

## Greedy loading rule

For a focused request, load every packet in this module unless its player moment is demonstrably outside the request. For a complete repository diagnostic, load every listed packet. The packets contain the operational procedure, evidence standard, repair patterns, deliverable rubric, and failure checks.

## Packets

- [game-design-failure-loop-audit](./capabilities/12-game-design-failure-loop-audit.md): trace a loss from expectation through retry and learning.
- [game-design-fairness-frustration-audit](./capabilities/13-game-design-fairness-frustration-audit.md): separate productive challenge from preventable frustration.
- [game-design-perceived-randomness-audit](./capabilities/36-game-design-perceived-randomness-audit.md): make variance legible, influenceable, and recoverable.

## Cross-domain checks

When a finding changes the player path, also load the adjacent module for fairness, pacing, player context, social impact, economy, and delivery feasibility. Do not treat this index as a substitute for the packets.
