# Game-design capability catalog

Use this catalog when the request is bare `game design`, asks what help is available, or asks which design review to run. Choose the player moment first, then load the listed packet and its neighboring domain modules when they could change the decision. For a complete repository review, use `full-diagnostic.md`; it loads all 61 packets. For “improve this game,” retention, churn, or engagement, use [autonomous improvement](./autonomous-improvement.md): it turns the diagnostic into an evidence-led improvement loop rather than a one-off report.

## Selection guide

- Start with the player moment and desired decision, not a framework name.
- Choose a packet if it directly names the decision. Add every adjacent packet whose findings could alter fairness, player fit, learning, social impact, economy, scope, or validation.
- If several packets fit, run them together and keep each packet’s evidence and output rubric visible in the report.
- If no packet fits cleanly, start with `design-red-team-audit`, `game-design-player-perspective-reframe`, and `game-design-option-generation`; they expose the decision, player moment, and alternatives.
- For `full audit`, `health check`, `design report`, or `review this game repository`, read the capability matrix, all domain modules, all 61 packets, then `full-diagnostic.md`.
