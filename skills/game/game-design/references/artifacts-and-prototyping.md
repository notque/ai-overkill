# Design artifacts and evidence-building prototypes

Use this module to create a document, pitch, canvas, or prototype that resolves a real decision.

## Greedy loading rule

For a focused request, load every packet in this module unless its player moment is demonstrably outside the request. For a complete repository diagnostic, load every listed packet. The packets contain the operational procedure, evidence standard, repair patterns, deliverable rubric, and failure checks.

## Packets

- [game-design-one-page-design-doc](./capabilities/32-game-design-one-page-design-doc.md): compress a decision-ready feature or game brief into one page.
- [game-design-pitch-deck-audit](./capabilities/37-game-design-pitch-deck-audit.md): test whether a pitch proves its player promise and production logic.
- [game-design-prototype-intent-audit](./capabilities/46-game-design-prototype-intent-audit.md): verify a prototype answers a decision-critical unknown.
- [game-design-prototyping-companion](./capabilities/47-game-design-prototyping-companion.md): plan prototype states, branches, and decision gates.
- [game-design-unknown-unknowns-prototyping](./capabilities/54-game-design-unknown-unknowns-prototyping.md): search for assumptions the current question set misses.

## Cross-domain checks

When a finding changes the player path, also load the adjacent module for fairness, pacing, player context, social impact, economy, and delivery feasibility. Do not treat this index as a substitute for the packets.
